# 송신 완료와 기한이 있는 종료

## 송신 회계

`send(bytes, tag)`가 `accepted`를 반환한 요청에는 선택 콜백 `on_write`를 정확히 한 번 호출한다. 거절된 요청에는 호출하지 않는다. tag는 호출자가 정하는 추적 값이며 중복 여부를 검사하지 않는다. 인자를 생략하면 0이다.

| 상태 | 의미 |
| --- | --- |
| written | 요청 전체의 로컬 쓰기 성공. bytes는 요청 크기, error는 비어 있음 |
| cancelled | 시작 전 폐기 또는 비동기 쓰기 취소. bytes는 취소 전 로컬 쓰기 완료량 |
| failed | 쓰기 I/O 오류. bytes는 오류 전 로컬 쓰기 완료량 |

원격 애플리케이션이 수신·처리했음을 의미하지 않는다. 실패나 취소에도 일부 바이트가 이미 전송됐을 수 있으므로 동일 요청의 재전송은 상위 프로토콜의 책임이다.

완료는 send 수락 순서로 전달한다. 진행 중인 쓰기의 완료를 회수한 뒤 미시작 요청들을 취소 통지하고, 모든 `on_write` 뒤에 `on_closed`를 한 번 호출한다. 각 요청의 버퍼와 예약량은 해당 콜백 전에 해제한다. `on_closed`에서는 pending 바이트·항목 수가 모두 0이다. 사용자 콜백은 잠금 밖에서 같은 strand로 직렬 실행한다.

`on_write` 안에서 send, close, close_after_flush를 호출할 수 있다. 콜백 예외는 실행 풀로 전파하지 않고 연결을 callback_error로 종료한다. 이미 확정한 종료 사유는 유지하며, 다른 수락 요청의 완료 통지를 생략하지 않는다. 기존 세 콜백만 지정한 소스는 on_write 없이 그대로 사용할 수 있다. 공개 API 변경 후 라이브러리와 소비자는 함께 다시 빌드한다.

## close_after_flush

- 절대 `steady_clock` 기한을 받는다. 호출 즉시 mutex 아래에서 새 send를 차단하고, 이후 수신 바이트를 사용자에게 전달하지 않는다. 이미 실행 중인 콜백과 외부 종료 요청은 겹칠 수 있다.
- start 전에도 사용할 수 있으며 수락한 송신만 자동으로 시작한다. 미리 큐에 넣은 응답을 보내고 종료하는 경로에 별도 start가 필요하지 않다.
- 진행 중 읽기만 개별 취소하여 쓰기를 계속한다. 수락한 쓰기와 읽기 취소 완료를 회수하면 송신 방향을 shutdown하고 소켓을 닫는다. 기한 타이머의 취소 완료까지 회수한 뒤 drained를 통지한다.
- drained는 로컬 송신이 끝났음을 뜻한다. 상대의 확인 응답이나 읽지 않은 상대 입력이 있는 경우의 EOF 관측까지 보장하지 않는다.
- 중복 호출은 첫 기한을 유지한다. 빈 큐도 이미 기한이 지났으면 drain_timeout, 기한 전이면 곧바로 drained로 종료한다.
- 기한 도달 시 drain_timeout과 timed_out 오류를 기록하고 진행 중 I/O를 취소한다. 타이머뿐 아니라 작업 진행 시에도 기한을 확인한다. 실행 문맥과 콜백이 멈춘 동안 실시간 강제 종료를 보장하지 않는다.
- close 또는 객체 파괴는 drain을 즉시 취소할 수 있다. drain 요청 자체는 최종 사유가 아니며, 성공·시간 초과·명시적 취소·I/O 오류 중 처음 확정된 종료 사유를 유지한다.
- 정상 종료 중에는 on_writable을 전달하지 않는다. 반환된 용량을 새 송신에 사용할 수 없기 때문이다.

## 검증 범위

정상 송신과 EOF, start 전 종료, 빈 큐, 만료된 기한, 읽지 않는 상대와 진행 중 쓰기의 타이머 취소, drain 중 파괴, 콜백 안 재송신·종료, 콜백 예외, 쓰기 실패, 여러 producer의 완료 순서, 송신·drain·즉시 종료 경쟁을 실제 localhost 소켓으로 검사한다. 기존 송수신·접속 수락 검사와 설치 소비자도 함께 실행한다.
