# 연결 수락·접속 계약

`establishment.hpp`의 `Listener`와 `Connector`는 TCP 연결을 준비하고 소켓 소유권을 호출자에게 전달한다. 게임 메시지나 세션을 만들지 않는다. 전달받은 `SerialSocket`은 `asio::ip::tcp::socket`으로 이동해 기존 `Connection`에 넘길 수 있다.

## 실행과 소유권

- 생성·파괴와 같은 객체의 다른 공개 함수 호출은 겹치면 안 된다. `start`, `cancel`, `resume`, `close`는 해당 클래스에서 제공하는 함수끼리 여러 스레드에서 호출할 수 있다.
- `start`와 종료 요청은 한 번만 예약된다. `resume`은 실행 중인 요청 외에 최대 한 개의 대기 요청으로 합친다.
- Listener의 콜백은 자체 strand에서 직렬 실행된다. 수락한 소켓은 각각 별도 strand를 가진다. Connector의 소켓·타이머·완료 통지는 같은 strand에서 실행된다.
- 생성자는 설정 및 bind/listen 오류를 예외로 보고한다. 비동기 접속·수락 오류는 결과 콜백으로 보고한다. 메모리 할당 실패와 Asio 작업 개시 예외를 복구하는 무예외 계약은 제공하지 않는다.
- 공개 객체 파괴는 종료 또는 취소를 요청한다. 실행 문맥은 객체보다 오래 살아야 하고 완료 통지까지 실행해야 한다. `io_context`를 먼저 멈추거나 파괴하면 통지는 보장하지 않지만, 대기 핸들러를 파괴하면 내부 상태도 해제된다.
- 소켓을 전달한 뒤에는 호출자가 소유한다. Listener/Connector를 닫거나 파괴해도 이미 전달한 소켓을 회수하지 않는다.
- 사용자 콜백 예외는 실행 풀로 전파하지 않는다. 접속 완료·종료 콜백의 예외로 두 번째 완료를 만들지 않는다. 사용자 콜백이 객체를 강하게 소유하는 순환 참조는 호출자가 피해야 한다.

## Connector

- 한 객체는 endpoint 한 개에 접속 한 번을 시도한다. DNS 조회·여러 주소 순회·자동 재시도는 수행하지 않는다. 실패 후 재시도는 새 객체로 시작한다.
- 원격 포트와 완료 콜백은 필수다. 기한은 `steady_clock::time_point` 절대 시각이며 이미 지난 기한도 유효한 입력이다. 실행 대기 시간까지 포함하고, 기한이 지났으면 접속을 시작하지 않는다.
- 결과는 `connected`, `cancelled`, `timed_out`, `io_error` 중 하나다. 성공일 때만 `socket`이 있으며 `error`는 비어 있다. 취소·기한 초과는 각각 `operation_aborted`, `timed_out` 오류를 준다.
- `cancel`은 `start` 전에도 가능하며 이후의 `start`는 새 접속을 만들지 않는다. 어느 경우든 실행 문맥을 구동하면 완료 통지가 정확히 한 번 발생한다.
- 결과를 확정하기 전 취소 요청을 관측하면 취소가 우선이다. 다음으로 현재 시각이 기한 이상이면 시간 초과로 확정한다. 커널 접속이 성공했더라도 완료 처리가 기한을 넘었으면 성공 소켓을 전달하지 않는다.
- 결과 확정 뒤의 취소는 결과를 바꾸지 않는다. 성공·실패·취소·기한 초과 모두 connect 및 timer 완료 핸들러를 회수한 뒤 통지한다. 실패 소켓은 닫히며, 완료 뒤에는 내부 작업이 전달된 소켓을 조작하지 않는다.

## Listener

- 생성 시 지정 주소에 bind/listen한다. 포트 0은 OS가 포트를 선택하게 하며, `local_endpoint`는 확정한 주소의 사본을 반환한다. backlog는 양수여야 한다. 주소 재사용 옵션은 자동으로 켜지 않는다.
- `start` 이후 pending accept는 최대 한 개다. 각 완료에서 새 소켓을 넘기고 다음 accept를 예약한다. 영구적인 accept 기한은 없으며, 서버의 수락 중지는 `close`로 제어한다.
- `on_accept`가 false를 반환하면 다음 수락을 멈춘다. `resume`으로 재개하며, 콜백 안에서 `resume`을 요청하고 false를 반환해도 재개 요청을 잃지 않는다. 커널 backlog의 연결을 세션으로 등록한 것은 아니다.
- `close`는 수락을 중단하고 대기 accept의 취소 완료를 회수한 뒤 `on_closed`를 한 번 호출한다. 시작 전이나 일시정지 중에도 종료할 수 있다. `on_closed` 뒤에는 `on_accept`가 오지 않는다. 이미 실행 중인 수락 콜백과 외부 close 요청은 겹칠 수 있다.
- 수락 오류는 `io_error`로 Listener를 종료한다. 오류를 즉시 무한 재시도하지 않는다. `on_accept` 예외는 `callback_error`로 종료한다. 이미 콜백에 넘긴 소켓의 소유권은 회수하지 않는다.
- 전체 연결 수·총 대기량·접속 빈도 제한, 수락한 연결의 등록과 서버 전체 종료는 상위 연결 관리 계층의 후속 범위다.

## 검증

실제 localhost 소켓으로 성공 및 소유권 이전, 접속 거절 후 새 시도, 만료된 기한과 완료 처리 지연, 시작 전후 취소, 수락 중단·재개, 대기 accept 종료, 객체 파괴, 콜백 예외, 여러 스레드의 중복 호출을 검사한다. 외부 서버의 응답이나 방화벽의 패킷 폐기를 시간 초과 재현 조건으로 사용하지 않는다.

`async-roundtrip`은 Listener → Connector → Connection을 연결해 실제 바이트 왕복을 확인한다. 설치 패키지 소비자도 같은 예제를 별도로 컴파일·링크·실행한다.
