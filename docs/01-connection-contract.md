# 첫 연결 계약

2026-10-11, 공개 인터페이스 초안. 첫 범위는 **이미 연결된 TCP 소켓의 바이트 송수신과 즉시 종료**이다. 첫 소켓 실험이며 최종 전투 통신 선택을 뜻하지 않는다.

## 소유권과 실행

- `Connection`은 전달받은 소켓을 소유한다. 호출자가 소켓을 다시 조작하면 안 된다.
- 실행 문맥과 작업 스레드는 호출자가 소유한다. 생성 뒤 콜백에서 사용할 객체를 준비하고 `start()`를 호출한다. `start()`는 중복 호출해도 한 번만 시작한다.
- 같은 연결의 소켓 조작·수신·송신 완료·종료 통지는 strand에서 직렬 실행한다. 특정 스레드에 고정하지 않는다. 서로 다른 연결의 콜백은 동시에 실행될 수 있다.
- `send`, `resume`, `close`, `pending`은 여러 스레드에서 호출할 수 있다. 객체 이동·파괴는 해당 공개 함수 호출과 겹치면 안 된다.
- 송신 입력은 수락 전에 소유 복사한다. 수신 span은 콜백이 반환할 때까지만 유효하다. 필요한 데이터는 사용하는 프로젝트가 제한된 저장 공간에 복사한다.

## 상한과 정체

- `send_bytes`와 `send_messages`는 대기열과 실제 전송 중인 버퍼를 함께 제한한다. 모든 제한은 양수여야 한다.
- 한 요청이 바이트 상한보다 크면 `too_large`, 빈 요청은 `empty`, 남은 공간이 부족하면 `would_block`이며 아무 바이트도 수락하지 않는다.
- `accepted`는 로컬 대기열 수락이다. 운영체제 쓰기 완료나 원격 게임의 처리 확인을 뜻하지 않는다.
- 큐에 넣기 전에 상한을 확인한다. 여러 `send`/`resume` 호출의 깨우기는 합쳐서 예약하므로 무제한 `post` 큐를 만들지 않는다. 연결당 예약 대기 깨우기 하나와 실행 중 깨우기, 읽기·쓰기 작업을 구분한다.
- `on_writable`은 `would_block` 이후 공간이 반환됐음을 알려준다. 다른 송신자가 먼저 사용할 수 있으므로 재시도 결과는 다시 확인한다.
- 고정 크기 `receive_chunk` 버퍼 하나만 사용한다. `on_bytes`가 false를 반환하면 다음 읽기를 멈춘다. `resume()` 요청이 실행되면 다시 읽는다. 콜백은 받은 청크 전체를 처리하거나 보관한 뒤 반환해야 한다.
- 이 상한은 라이브러리 소유 송신 데이터와 수신 청크에 관한 것이다. 운영체제 소켓 버퍼·호출자 복사본·메모리 할당자 부가 공간·전체 연결 수까지 제한하는 수치는 아니다.

## 종료와 오류

- `close()`는 즉시 새 송신을 거절한다. strand가 소켓을 닫고 대기 송신을 버린다. 쓰기 중인 버퍼는 취소 완료까지 유지한다.
- 종료 요청과 이미 실행 중인 콜백은 겹칠 수 있다. `on_closed` 이후에는 다른 사용자 콜백이 오지 않는다. 종료 완료 시 `pending()`은 0이다.
- 종료 통지는 진행 중인 읽기·쓰기 완료를 회수한 후 한 번만 전달한다. 로컬 종료, 상대 종료, 입출력 오류, 콜백 예외를 구분하며 최초 종료 사유가 유지된다. 상대의 송신 종료는 첫 구현에서 연결 전체 종료로 취급한다.
- 콜백은 짧게 실행하고 예외를 던지지 않는 것이 계약이다. 수신·공간 통지의 예외는 연결을 실패 종료한다. 종료 통지의 예외는 실행 문맥 밖으로 전파하지 않는다.
- 객체 파괴도 종료를 요청한다. 실행 문맥은 연결보다 오래 살아야 하며 종료 완료까지 실행해야 한다. 호출자가 실행 문맥을 먼저 정지하면 완료 통지를 보장할 수 없다. 콜백이 연결 소유자를 강하게 붙잡는 순환 참조를 만들지 않는다.
- 메모리 할당 실패와 Asio 작업 개시 예외를 복구하는 무예외 계약은 제공하지 않는다. 특히 메모리 고갈을 정상적인 정체 결과로 취급하지 않는다.

## 이번 범위에 없는 것

리스너의 연결 수 제한, 대기 송신 후 종료, TLS, 프레이밍, 직렬화, 인증, 재접속, 게임 세션·Room 연결, 성능 목표는 구현하지 않았다. 비동기 연결 수락과 기한·취소가 있는 접속 시작은 별도 [Listener·Connector 계약](03-establishment-contract.md)으로 제공한다.

게임 통합 전에는 기존 프레이밍과 세션을 연결하는 별도 코드를 만들고, 접속·세션 기한 및 정체·종료 계약을 함께 검사한다. 현재 Asio socket 타입이 공개 헤더에 있으므로 사용 프로젝트도 동일한 standalone Asio 버전을 필요로 한다. 다중 백엔드 추상화는 하지 않는다.
